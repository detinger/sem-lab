# 05 · Service quality → satisfaction → loyalty with CB-SEM (and how it differs from PLS)

*SEM Lab Colab collection, notebook 5 of 5. Data: **SYNTHETIC** (generated in this
notebook). Estimation: SEM Lab's own engine (Python), no R required.*

**Attribution.** The model follows the service quality → satisfaction → loyalty chain discussed,
for example, by Cronin, J. J., & Taylor, S. A. (1992). Measuring service quality: a
reexamination and extension. *Journal of Marketing, 56*(3), 55–68, and Zeithaml, V. A., Berry,
L. L., & Parasuraman, A. (1996). The behavioral consequences of service quality. *Journal of
Marketing, 60*(2), 31–46. The data are **synthetic** teaching data generated by SEM Lab; they
do not reproduce any published dataset. This notebook is the Python companion of SEM Lab's
example *"Service quality → satisfaction → loyalty (CB-SEM)"* and uses byte-identical data.

### Learning objectives

After this notebook you can

1. specify and estimate a **confirmatory factor analysis** (CFA) and a structural equation model
   by maximum likelihood (covariance-based SEM, CB-SEM);
2. explain identification (marker indicator), degrees of freedom and the χ² test;
3. judge **global fit** with χ², CFI, TLI, RMSEA (with its confidence interval) and SRMR, and see
   how a wrong model shows up in these indices;
4. compute an indirect effect in CB-SEM and state what is (and is not) available for it;
5. compare the **estimands** of CB-SEM, consistent PLS (PLSc) and classic PLS-SEM on the same data.

### Theory and *illustrative* hypotheses

| | Hypothesis (illustrative) |
|---|---|
| H1 | Service quality (SQ) → customer satisfaction (SAT) (+) |
| H2 | SAT → loyalty intentions (LOY) (+) |
| H3 | SQ → LOY, direct effect (+) |
| H4 | SAT mediates the effect of SQ on LOY |

All three constructs are measured reflectively by 4–5 items, so they are modelled as **common
factors**: each item = loading × factor + error. That is the model CB-SEM estimates. The data
are synthetic and cross-sectional: the arrows are assumptions, not demonstrated causes.

### Why SEM Lab's engine and not semopy?

SEM Lab's plan names *semopy* for this notebook. The estimates below come from SEM Lab's
own engine instead, the same one the app uses: it reproduces lavaan 0.7-3 (the reference
implementation the app is verified against) for ML and MLR estimates, standard errors and fit
indices, whereas semopy uses different estimator and fit-index definitions in places, so its
numbers cannot be guaranteed to match the app. Section 10 fits the same model with semopy as an
**optional cross-check** and compares the ML point estimates.

## 5. Measurement model first: confirmatory factor analysis

A CFA lets every pair of factors correlate freely and has no directional paths. If the CFA does
not fit, the structural model cannot fit either, so we check it first.

**Identification.** A factor has no natural scale. With *marker* identification the first
loading of each factor is fixed to 1, so the factor takes that item's metric (the default of
lavaan and of SEM Lab). Standardised estimates do not depend on this choice.

**Degrees of freedom.** 13 items give 13·14/2 = 91 variances and covariances. The CFA estimates
10 free loadings, 13 error variances, 3 factor variances and 3 factor covariances = 29
parameters, leaving df = 62.

%% code
import time

cfa_model = json.loads(MODEL_JSON)
cfa_model["relationships"] = [
    {"id": f"r_{a}_{b}", "kind": "covariance", "sourceId": f"c_{a}", "targetId": f"c_{b}"}
    for a, b in [("sq", "sat"), ("sq", "loy"), ("sat", "loy")]]
analysis = {"method": "cb-sem", "engine": "browser", "estimator": "ML", "missingData": "listwise",
            "cb": {"identification": "marker", "meanStructure": False}}

columns, data_rows = semlab.read_csv("data.csv")
data = semlab.build_analysis_data(model, columns, data_rows, "listwise")
t0 = time.perf_counter()
out_cfa = semlab.estimate(cfa_model, analysis, data)
print(f"CFA estimated in {time.perf_counter() - t0:.2f} s")
assert out_cfa["ok"], out_cfa.get("error")
cfa = out_cfa["result"]
print(cfa["estimation"]["messages"][0])
cfa_tables = semlab.to_dataframes(cfa, cfa_model)


def fit_table(result_):
    f = pd.DataFrame(semlab.results_tables(result_, model)["fit"])
    f["variant"] = f["variant"].fillna("standard")
    keep = ["chisq", "df", "pvalue", "cfi", "tli", "rmsea", "srmr", "aic", "bic"]
    f = f[f["name"].isin(keep)]
    f["name"] = pd.Categorical(f["name"], keep, ordered=True)
    return f.sort_values(["variant", "name"]).set_index(["variant", "name"])[["value", "ciLower", "ciUpper"]]


show(fit_table(cfa), 4)

%% markdown
**Interpretation of global fit.**

| Index | Here | Common guideline |
|---|---|---|
| χ² test | χ²(62) ≈ 62.4, p ≈ 0.46 | non-significant p is consistent with exact fit (very sensitive to N) |
| CFI / TLI | ≈ 1.00 | ≥ 0.95 |
| RMSEA (90% CI) | ≈ 0.004 (0.000–0.029) | ≤ 0.06; upper CI limit ≤ 0.08 |
| SRMR | ≈ 0.02 | ≤ 0.08 |

Every index indicates excellent fit — no surprise, because the data were generated from exactly
this factor structure. Real data rarely fit this well; guidelines are heuristics, not
significance tests, and should be read together.

%% code
load = cfa_tables["loadings"][["from", "to", "est", "se", "pValue", "std"]].rename(
    columns={"from": "factor", "to": "indicator", "est": "unstd. loading", "std": "std. loading"})
show(load)
lat = cfa_tables["matrix:latent-correlations"].set_index("")
lat.index.name = None
print("Latent (factor) correlations:")
show(lat.astype(float))

%% markdown
**Construct reliability and AVE from the CFA.** With standardised loadings λ, composite
reliability is CR = (Σλ)² / ((Σλ)² + Σ(1 − λ²)) and AVE = mean(λ²). These are the
common-factor counterparts of PLS's ρC and AVE.

%% code
rel = load.groupby("factor", sort=False)["std. loading"].agg(
    CR=lambda l: l.sum() ** 2 / (l.sum() ** 2 + (1 - l ** 2).sum()), AVE=lambda l: (l ** 2).mean())
show(rel)

%% markdown
**Interpretation.** All standardised loadings are between about 0.66 and 0.85 and significant,
CR exceeds 0.80 for every factor, and AVE reaches 0.50 (SQ sits right at the threshold, SAT and
LOY are clearly above it). The factor correlations (about 0.52–0.70) are clearly below 1, and
√AVE of each factor exceeds its correlations, so the three factors are distinct.

%% markdown
**Interpretation.** All three paths are positive and significant (z tests with ML standard
errors; the CIs are Wald intervals). In standardised terms, SQ → SAT ≈ 0.55, SAT → LOY ≈ 0.60
and the direct SQ → LOY ≈ 0.19 (population: 0.60, 0.55, 0.25). The fit is **identical** to the
CFA: with three factors and three paths, the structural part is just-identified (it uses
exactly as many parameters as the three factor correlations), so the structural model is an
equivalent re-parameterisation of the CFA. Its fit says nothing about the direction of the
arrows: SAT → SQ would fit exactly as well.

### Indirect effect (H4)

%% code
std = paths.set_index("path")["std"]
unstd = paths.set_index("path")["est"]
a_s, b_s, c_s = std[f"SQ {ARROW} SAT"], std[f"SAT {ARROW} LOY"], std[f"SQ {ARROW} LOY"]
ind_std = a_s * b_s
print(f"standardised: indirect SQ -> SAT -> LOY = {a_s:.3f} x {b_s:.3f} = {ind_std:.3f}; "
      f"direct = {c_s:.3f}; total = {ind_std + c_s:.3f}")
print(f"unstandardised: indirect = {unstd[f'SQ {ARROW} SAT'] * unstd[f'SAT {ARROW} LOY']:.3f}")

%% markdown
**Interpretation.** The indirect effect is the product of the two paths (about 0.33 standardised,
population 0.33), so H4 is supported as a point estimate: more than half of SQ's total effect
on LOY runs through satisfaction. **What is not available here:** a confidence interval for the
indirect effect. Products of coefficients need a bootstrap or Monte Carlo interval, and SEM
Studio does not offer a CB-SEM bootstrap in this version (the app states this limitation instead
of approximating it). Notebook 01 shows how the PLS bootstrap tests an indirect effect; for a
CB-SEM interval, use lavaan's bootstrap in R.

## 7. Robustness: MLR

MLR gives the same point estimates as ML but standard errors and a test statistic
(Yuan–Bentler scaled χ²) that are robust to non-normal data.

## 8. CB-SEM, PLSc and classic PLS-SEM: different estimands

The same diagram means different things to different estimators:

- **CB-SEM** estimates relationships between **common factors** (error-free latent variables).
- **PLSc** (consistent PLS) estimates the same common-factor quantities through a correction of
  composites for their reliability.
- **Classic PLS-SEM** estimates relationships between **composites** (weighted sums of the
  observed items, which still contain measurement error). Its population values are *attenuated*
  correlations: a different estimand, not a biased estimate of the factor model's parameters.

The generator gives us both truths: the factor-model population values and the population limit
of classic PLS (what classic PLS would estimate with infinite data on the continuous responses).

%% code
truth = derived_truths(pop)["classicPlsPopulationLimit"]["paths"]
pls_limit = {(p["source"], p["target"]): p["coefficient"] for p in truth}
factor_truth = {(s, t): b for s, t, b in pop["spec"]["paths"]}

pls_analysis = {"method": "pls-sem", "engine": "browser", "estimator": "pls-pm", "missingData": "listwise",
                "pls": {"innerWeighting": "path", "maxIterations": 300, "tolerance": 1e-7}}
est_by = {}
for label, a_ in [("classic PLS-SEM", pls_analysis), ("PLSc", dict(pls_analysis, method="plsc"))]:
    o = semlab.estimate(model, a_, data)
    assert o["ok"], o.get("error")
    est_by[label] = semlab.to_dataframes(o["result"], model)["paths"].set_index(["from", "to"])["est"]
est_by["CB-SEM (ML, standardised)"] = tables["paths"].set_index(["from", "to"])["std"]

rows_ = []
for (s, t), b in factor_truth.items():
    rows_.append({"path": f"{s} {ARROW} {t}", "population: common factors": b,
                  "CB-SEM (ML, std.)": est_by["CB-SEM (ML, standardised)"][(s, t)],
                  "PLSc": est_by["PLSc"][(s, t)],
                  "classic PLS-SEM": est_by["classic PLS-SEM"][(s, t)],
                  "population limit of classic PLS": pls_limit[(s, t)]})
estimands = pd.DataFrame(rows_)
show(estimands)

%% code
fig, ax = plt.subplots(figsize=(7.4, 3.4))

%% markdown
**Interpretation.** CB-SEM and PLSc target the same common-factor quantities and, on the same
data, agree to about 0.005. Classic PLS gives clearly smaller values for SQ → SAT (0.48 vs
0.55) and SAT → LOY (0.53 vs 0.60): the composites still contain measurement error, which
attenuates their correlations. Even with infinite data classic PLS would not reach the factor
values; it converges to its own population limit (e.g. 0.53 instead of 0.60 for SQ → SAT). The
distance between any single estimate and its population value (about ±0.05 here) is sampling
error plus the effect of 7-point categories, and it affects all estimators alike; the
*systematic* difference is the one between estimators on the same data. Neither estimator is
"wrong": they answer different questions. Report which estimator you used, never mix CB and classic PLS numbers in
one table as if they were the same quantity, and choose the estimator from the nature of the
constructs (common factors vs composites) and the research goal (theory testing vs prediction).

## 10. Optional cross-check with semopy

This section is **optional** and is *not* the notebook's result. It fits the same model with
semopy {{SEMOPY_VERSION}} (installed in the next cell if it is missing; on Colab this adds
semopy and numdifftools and does not touch numpy, scipy or pandas) and compares the
unstandardised ML estimates with SEM Lab's. In our tests they agree to within 1e-3
(semopy stops its optimiser earlier than lavaan and SEM Lab, which agree to about 1e-6).
Set `RUN_SEMOPY_CROSSCHECK = False` to skip it.

%% code
RUN_SEMOPY_CROSSCHECK = True  #@param {type:"boolean"}
SEMOPY_VERSION = "{{SEMOPY_VERSION}}"
TOLERANCE = 1e-3

if RUN_SEMOPY_CROSSCHECK:
    try:
        import semopy
        if semopy.__version__ != SEMOPY_VERSION:
            raise ImportError(f"semopy {semopy.__version__} found, {SEMOPY_VERSION} wanted")
    except ImportError:
        get_ipython().run_line_magic("pip", f"install -q semopy=={SEMOPY_VERSION}")
        import semopy
    description = "\n".join(
        [f"{c['name']} =~ " + " + ".join(names_of(model)[i] for i in c["indicatorIds"]) for c in model["constructs"]]
        + ["SAT ~ SQ", "LOY ~ SQ + SAT"])
    print(description)
    sem = semopy.Model(description)
    sem.fit(df[[i["column"] for i in model["indicators"]]], obj="MLW")
    ins = sem.inspect()
    ours = tables["parameters"]
    rows_ = []
    for _, r in ins.iterrows():
        if r["op"] == "~" and r["rval"] in ("SQ", "SAT", "LOY") and r["lval"] in ("SAT", "LOY"):
            key = f"path:c_{r['rval'].lower()}->c_{r['lval'].lower()}"
        elif r["op"] == "~":  # semopy writes loadings as indicator ~ factor
            key = f"loading:c_{r['rval'].lower()}:i_{r['lval']}"
        else:
            continue
        mine = ours.set_index("key").loc[key, "est"]
        rows_.append({"parameter": key, "SEM Lab": mine, "semopy": float(r["Estimate"]),
                      "abs. difference": abs(mine - float(r["Estimate"]))})
    crosscheck = pd.DataFrame(rows_)
    show(crosscheck, 5)
    worst = crosscheck["abs. difference"].max()
    print(f"max |difference| = {worst:.1e} (tolerance {TOLERANCE:g}) -> {'agree' if worst < TOLERANCE else 'DIFFER'}")
    assert worst < TOLERANCE

## 12. Summary and questions

- The three-factor CFA fits excellently (χ²(62) ≈ 62, CFI ≈ 1.00, RMSEA ≈ 0.004, SRMR ≈ 0.02);
  a one-factor model fails clearly.
- SQ → SAT, SAT → LOY and SQ → LOY are positive and significant; about 0.33 of SQ's total
  standardised effect on LOY runs through SAT (point estimate; no CB bootstrap here).
- CB-SEM and PLSc estimate common-factor relationships; classic PLS-SEM estimates composite
  relationships, which are attenuated. The numbers answer different questions.

**Questions**
